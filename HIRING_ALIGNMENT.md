# Hiring Alignment

## Role Signal: Basketball Curiosity and Judgment

The model is framed around basketball decisions, not abstract prediction. Outputs compare lineup profiles by expected possession value, defensive risk, role fit, sample size, and uncertainty.

## Role Signal: Technical Rigor

The workflow includes time-based validation, model error metrics, bootstrap uncertainty, sample-size shrinkage, and assumption documentation.

## Role Signal: Practical Builder

The project runs from one script, creates a local SQLite analytics layer, trains a model, and writes stakeholder-ready CSVs, charts, and markdown briefs.

## Role Signal: Clear Communicator

The executive brief separates the recommendation, evidence, limitations, and next analysis steps so basketball stakeholders can understand what to trust and what not to overread.

## Role Signal: Ownership Mindset

The project starts from an ambiguous question and moves to a complete artifact: data generation, modeling, validation, visualization, written interpretation, and reusable documentation.

## Role Signal: Collaboration With Engineering

The output tables are clean, deterministic, and versionable. In a production setting, these could become scheduled data products or dashboard tables owned with Engineering.

## Honest Boundary

This is not professional NBA analytics experience and it does not claim access to Phoenix Suns internal data. It is a public work sample showing how Neel would approach the type of basketball decision-support work described in the job posting.
